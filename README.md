# 云笈仙田录

云笈仙田录是一个基于 Electron + JavaScript 的本地配置驱动游戏项目，当前阶段目标是先跑通 2D 等距伪3D 的可玩 MVP，并沉淀一套可持续扩展的工具链与目录规范。

## 1. 项目目标

当前阶段核心目标：
- 先跑通配置驱动主循环，而不是先做大而全内容。
- 明确代码层、配置层、资源层、工具层边界，减少耦合。
- 用成熟依赖优先，避免重复造轮子。

当前 MVP 范围：
- 种植系统
- 技能系统（简版）
- 任务系统
- 角色交互
- 采集系统
- 物块建造系统

暂不纳入当前迭代：
- 阵法、符箓、修炼、功法、炼丹、炼器

## 2. 技术基线

- 运行环境：Electron + Vite + JavaScript
- 游戏渲染：Phaser 路线（方案 A）
- 配置解析：YAML + Schema 校验
- 规则执行：状态机 + 规则表达式
- 动画系统：Spine 运行时
- 音频：Howler

依赖与版本基线见：
- [依赖清单-方案A.md](docs/tool-guides/依赖清单-方案A.md)

## 3. 目录总览

根目录下的主要业务目录：

- [apps](apps): 运行时入口与本地工具应用
- [src](src): 核心代码（系统、世界、UI 运行时、动画）
- [configs](configs): 配置与 Schema（玩法、UI、换肤、本地化）
- [assets](assets): 资源源文件、运行时资源、资源包
- [tools](tools): 配置校验、编译、监听、迁移、冒烟工具
- [scripts](scripts): 开发、构建、验证脚本
- [storage](storage): 本地存档、设置、缓存、日志
- [tests](tests): 单元、集成、冒烟测试
- [docs](docs): 架构、字段字典、工具指南、测试计划

各一级目录已放置说明文件，详见各目录下 `README.md`。

## 4. 开发原则

### 4.1 配置驱动优先
- 优先通过 `configs` 定义玩法、UI、规则与资源映射。
- 避免将业务规则硬编码在运行时逻辑中。
- 新功能尽量以“数据 + 执行器”模式落地。

### 4.2 分层边界清晰
- `src/systems` 负责玩法逻辑。
- `src/world` 负责地图网格与地块规则。
- `src/ui-runtime` 负责配置化 UI 渲染与换肤。
- `tools` 负责校验、构建、迁移、验证，不混入运行时业务。

### 4.3 UI 与换肤约束
- UI 结构与交互逻辑不因皮肤而改变。
- 皮肤仅覆盖 token 与资源映射。
- 缺失资源必须走回退链，不允许因皮肤缺项导致崩溃。

## 5. 开发流程（建议）

新增/修改功能时建议遵循：
1. 在 `configs/schema` 扩展或确认配置结构。
2. 在 `configs/gameplay` 或 `configs/ui` 增加配置。
3. 在 `src/systems` 或 `src/ui-runtime` 增加执行逻辑。
4. 使用 `tools` 完成配置校验与编译。
5. 用 `tests` 补充关键路径测试。
6. 更新文档（本 README + 相关专题文档）。

## 6. 验证要求

代码和配置变更后至少完成：
- 语法/类型错误检查（无错误）
- 启动验证（Vite + Electron 可正常启动）
- 运行时日志检查（无新增阻塞性错误）
- 必要时执行冒烟测试

已知可忽略告警需在变更说明中明确注明原因。
