# 云笈仙田录代码约束规范（草案 v1）

> 目标：在保持当前项目代码风格与设计规范一致的前提下，提供可执行、可评审、可落地的工程约束。
>
> 适用范围：本仓库所有 JS/MJS 源码、YAML UI 配置、流程配置、主题配置，以及主进程与渲染进程桥接代码。

## 1. 约束等级

- M（强制）：违反即阻断合并。
- S（建议）：允许临时例外，但必须在评审中给出理由与回收计划。
- O（可选）：最佳实践，不作为阻断项。

## 2. 架构分层约束

### 2.1 配置驱动（M）

- UI 结构必须由 YAML 定义，不允许在业务代码中硬编码页面组件树。
- 页面、流程、主题分别由独立配置承载：
  - 页面注册：scenes/ui-registry.yaml
  - 流程编排：scenes/ui-flow.yaml
  - 主题令牌：scenes/theme.yaml
  - 页面场景：scenes/panel/*.yaml

### 2.2 服务边界（M）

- 保持服务职责单一，不跨层读写内部状态：
  - RegistryService：页面注册与别名解析
  - FlowService：节点、转场与回退规则
  - SceneService：场景加载、主题注入、最小结构校验
  - UIRenderer：组件渲染与 action 事件分发
  - FlowRuntime：节点进入、动作处理、计时器调度
  - ActionBus：通道消息分发
- 启动装配统一由 AppBootstrap 完成，禁止在多个入口重复拼装运行时。

### 2.3 最小改动原则（S）

- 变更应聚焦需求本身，避免“顺手重构”无关代码。
- 不修改与本需求无关的命名、格式、接口行为。

### 2.4 四域分层与深度隔离（M）

- 所有 Scene 界面必须严格归属于以下四类 Domain，并存放于 `scenes` 下的对应目录：
  - `world` (主世界与模拟层)，深度号段预留：**0 - 999**
  - `hud` (常驻信息层)，深度号段预留：**1000 - 1999**
  - `panel` (交互面板层)，深度号段预留：**2000 - 2999**
  - `system` (系统与过渡层)，深度号段预留：**3000 - 3999**
- **防越权规定**：绝对禁止跨 Domain 抢夺深度号段（如：panel 层的 depth 不得大于 2999）。
- 新增层级必须优先使用域内空槽号段，禁止挪用或顺延已有层编号。

## 3. YAML 与流程配置约束

### 3.1 注册与可达性（M）

- 所有流程节点必须具备至少一条跳转边 (transition) 或配置 `fallback` 兜底，禁止存在“无法离开”的死胡同节点。

### 3.3 场景最小结构与组件载荷（M）

- 每个 scene 至少包含：page、layers、components。
- page.id 必填。
- layers 与 components 必须为数组。
- 组件 layer 必须在 layers 中存在。
- **组件合法载荷检查**：
  - `button`：必须包含 `text` 或 `binding`，且必须声明 `actionId` 或 `eventId`。
  - 动态组件（`dynamicText`, `slider`, `toggle` 等）：必须包含 `binding` 属性映射数据路径。
  - 嵌套边界：`children` 属性仅允许出现在容器型组件（如 `stack`, `panel`, `rectangle`）中，禁止挂载于叶子组件
- flow.entry 必须存在且指向有效节点。
- transitions.to 与 fallback 必须指向已存在节点。
- transitionPresets 引用必须可解析。

### 3.3 场景最小结构（M）

- 每个 scene 至少包含：page、layers、components。
- page.id 必填。
- layers 与 components 必须为数组。
- 组件 layer 必须在 layers 中存在。

### 3.4 主题与样式令牌（M）

- 页面样式优先引用 theme token，禁止在页面配置中硬编码业务配色。
- 允许个别必要常量（如局部尺寸）使用字面量，但需保证跨页面一致性。

## 4. UI 视觉与交互约束

### 4.1 整窗基准（M）

- 页面布局以当前窗口内容区为基准，先主结构后局部组件。
- 页面禁止横向与垂直滚动与卡片层禁止横向滚动。
- 功能卡片不得越出可视内容区，超量内容仅允许卡片内部纵向滚动。

### 4.2 像素风边框按钮（M）

- 所有带边框按钮必须为像素风语义：直角或像素切角、整数像素描边。
- 禁止圆角胶囊、柔光描边、拟物高光边框。
- 边框颜色、背景色、文字色优先来自主题令牌。
# 4.4 输入穿透与焦点控制（M）

- **面板拦截**：当 `panel` 域界面打开时，必须对底层 `world` 域输入进行降级或暂停处理。
- **模态阻塞**：任何标记为 `modal` 的区域或 `system.blocker/system.alert`，展示期间必须启用全局阻塞层拦截所有下层点击穿透。
- **通信边界**：焦点控制只允许通过统一事件总线（如 `ui.openPanel`, `world.pauseInput`）派发，UI 组件禁止直接互调对象方法。

##
### 4.3 动态内容绑定（S）

- 动态文本优先走数据绑定，不推荐在运行时代码里查找组件并逐一改文案。

## 5. 运行时行为约束

### 5.1 动作通道统一（M）

- button 必须声明 actionId。
- 所有 UI 动作统一进入 actionChannel（默认 ui.action），不得绕过总线直接跳节点。

### 5.2 启动门禁（M）

- Runtime 启动前必须完成：
  1. Registry 加载成功
  2. Flow 加载成功
  3. Theme 加载成功
  4. FlowValidator 校验通过
- 任一步失败必须阻断启动。

### 5.3 定时器安全（M）

- 节点切换时必须清理旧计时器，防止幽灵触发导致错页跳转。

## 6. 错误处理与可观测性约束

### 6.1 统一错误模型（M）

- 统一使用断言 + 结构化错误对象。
- 禁止抛出字符串或无 code 的散装错误。

### 6.2 错误码集中管理（M）

- 所有业务错误码必须来自统一错误码定义。
- 禁止在业务代码中临时拼接魔法字符串错误码。

### 6.3 安全读配置（M）

- YAML 读取必须经过统一读入层，具备：
  - 文件存在性检查
  - 类型检查
  - 解析失败分级
  - 安全返回结构（ok/code/message/details）

### 6.4 诊断信息最小集合（S）

- 错误 details 至少包含路径或关键标识（如 filePath、pageId、nodeId、actionId）。

## 7. 命名与编码风格约束

### 7.1 风格一致性（M）

- 保持当前仓库既有风格：ESM 模块、稳定注释风格、语义化方法命名。
- 公有服务对外暴露稳定快照接口，避免直接暴露可变内部结构。

### 7.2 防御式校验（S）

- 对外输入优先校验再执行核心逻辑。
- 关键路径保持 fail-fast，避免静默吞错。

## 8. 变更流程约束

### 8.1 变更闭环（M）

- 新增或修改页面时必须同步检查：
  1. scenes/ui-registry.yaml 是否注册
  2. scenes/ui-flow.yaml 是否可达
  3. scenes/panel/*.yaml 是否存在且结构合法

### 8.2 新组件类型扩展（M）

- 新增组件类型时必须同时完成：
  1. 渲染器支持
  2. 场景校验规则补齐
  3. 至少一个真实页面接入验证

### 8.3 文档同步（S）

- 影响 UI 规范的变更需同步更新 docs/ui-constraints.instructions.md。

## 9. 禁止项（红线）
**【配置与结构专检】**
- [ ] 页面注册 (registry)、流程跳转边 (transitions)、场景 YAML 文件三者闭环，无死胡同。
- [ ] flow.entry、transitions.to、fallback 全部可解析。
- [ ] 场景 Domain 类型划分正确（属于 world/hud/panel/system 之一），存放目录正确。
- [ ] 组件与层级 Depth 未超出该域的规定号段范围（0-999, 1000-1999, 2000-2999, 3000-3999）。
- [ ] 场景结构合法（page/layers/components 完整），动态组件包含 binding，容器组件才包含 children。
- [ ] 启动链路门禁有效（registry/flow/theme/validator/runtime）。
- [ ] 错误码、断言、错误返回结构符合统一模型。

**【UI 视觉与防穿透专检】**
- [ ] 页面优先定义整窗结构且主操作区处于视觉焦点。
- [ ] 弹出面板或模态层正确启用了输入阻塞，无点击穿透到底层世界的隐患。
- [ ] 按钮等交互组件正确绑定了 actionId 或 eventId，所有显式边框按钮均为像素风直角或切角，绝对无圆角或拟物特征。
- [ ] YAML 之中无硬编码的主配色和关键尺寸，全部正确引用于主题 `$colors.*`, `$components.*` 等 token

## 10. 评审清单（可直接用于 PR）

### 10.1 必过项（M）

- [ ] 页面注册、流程可达、场景文件三者闭环。
- [ ] flow.entry、transitions.to、fallback 全部可解析。
- [ ] scene 结构合法（page/layers/components 完整）。
- [ ] 样式 token 化满足要求，边框按钮满足像素风规则。
- [ ] 启动链路门禁有效（registry/flow/theme/validator/runtime）。
- [ ] 错误码、断言、错误返回结构符合统一模型。

### 10.2 建议项（S）

- [ ] 改动范围聚焦且不引入无关重构。
- [ ] 异常 details 含关键定位信息。
- [ ] 受影响文档已同步更新。

## 11. 执行建议（下一步）

- 建议后续增加自动化机检脚本，对以下项做 CI 阻断：
  1. flow 与 registry 交叉一致性检查
  2. scene 最小结构检查
  3. token 使用率检查（页面硬编码色彩告警）
  4. 禁止模式扫描（硬编码 UI 构造、未定义错误码）
