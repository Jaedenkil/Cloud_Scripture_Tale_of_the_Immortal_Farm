# 开发工具规划与角色规格（配置驱动MVP）

## 0. 目标范围

当前阶段目标：先跑通核心玩法闭环，包含以下系统：

- 种植系统
- 技能系统（简版）
- 任务系统
- 角色交互
- 采集系统
- 物块建造系统

暂不纳入当前开发范围：阵法、符箓、修炼、功法、炼丹、炼器。

## 1. 参考案例

参考：星露谷物语 的 数据驱动内容组织  
实现方式：作物、物品、任务通过数据定义，代码负责通用执行器。  
适用性：适用  
本项目调整：先将种植、采集、任务、交互统一配置化，减少硬编码。

参考：Terraria 的 地块与掉落规则驱动  
实现方式：地块行为与掉落走规则表，运行时解释执行。  
适用性：适用  
本项目调整：物块建造、采集掉落、过渡模式优先规则化。

参考：Minecraft 的 资源包覆盖与回退  
实现方式：资源覆盖链，未覆盖项回退默认包。  
适用性：适用  
本项目调整：UI 皮肤与资源管理器采用同样回退机制。

## 2. 开发工具总览（按必要性）

### 2.1 必须优先（MVP 必备）

1. 配置 Schema 校验器

- 作用：字段类型、必填项、引用合法性、版本兼容校验。
- 产出：可读错误报告（定位到文件/字段）。

2. 配置编译器

- 作用：合并多份配置，生成运行时快照数据。
- 支持：继承覆盖、默认值注入、变量替换、资源别名解析。

3. 本地热重载服务

- 作用：修改配置后游戏内快速生效。
- 支持：增量刷新、失败回滚、错误浮层提示。

4. 游戏内调试控制台

- 作用：查看状态树、事件流、规则命中结果。
- 支持：命令注入、状态快照导出、关键日志筛选。

5. 物块编辑器（必须）

- 作用：编辑地块属性、建造规则、采集规则、掉落、过渡模式 A/B/C。
- 说明：建造、采集、种植均依赖该工具，为核心底座。

6. 本地资源管理器（必须）

- 作用：管理贴图、音频、Spine 资源、UI 皮肤资源与配置引用关系。
- 支持：资源导入、重命名、引用追踪、缺失回退、冲突检测。

### 2.2 建议尽快（MVP+）

7. 任务与对话编辑器

- 作用：任务状态机与对话分支配置化。
- 支持：触发条件、步骤、奖励、失败路径、分支一致性校验。

8. 技能编辑器（简版）

- 作用：技能定义与依赖关系配置化。
- 支持：冷却、消耗、效果挂点、前置条件。

9. 人物动画管理器（Spine 最小版）

- 作用：动画状态绑定与预览，不追求 DCC 全功能。
- 支持：idle/walk/work/interact/hurt/death 状态映射、事件帧标记。

### 2.3 第二阶段补齐

10. 存档迁移工具

- 作用：配置版本升级后自动迁移旧存档。

11. 自动化验收工具

- 作用：配置静态检查、核心流程冒烟、性能采样。

## 3. 最小可跑闭环（建议先做 6 项）

- 配置 Schema 校验器
- 配置编译器
- 本地热重载服务
- 游戏内调试控制台
- 物块编辑器
- 本地资源管理器

这 6 项即可支撑“地图地块 + 采集建造 + 基础种植 + 任务触发 + 角色交互”的可运行版本。

## 4. 物块编辑器能力边界

### 4.1 数据项

- 地块类型、层级、可通行性
- 建造条件（材料、工具、环境）
- 采集条件（工具等级、耗时、体力）
- 掉落规则（固定/概率/权重）
- 过渡模式（A 自动拼接 / B 侵入融合 / C 硬边）

### 4.2 可视化需求

- 16x16 基础网格显示
- 邻接规则预览
- 高度差侧面显隐预览
- 侵入融合方向预览

## 5. 本地资源管理器能力边界

### 5.1 资源分类

- 贴图资源（地块、UI、特效）
- 动画资源（Spine skeleton/json/atlas/texture）
- 音频资源
- 配置资源（yaml/json）
- 皮肤包资源

### 5.2 核心能力

- 资源导入与规范命名校验
- 语义别名管理（逻辑名到实际文件）
- 被引用关系追踪（反查哪些配置在用）
- 缺失资源自动回退（当前皮肤 -> 默认皮肤 -> 内置保底）
- 打包前完整性检查

## 6. 人物动画管理器（Spine）建议

### 6.1 当前阶段目标

- 做“运行时预览 + 状态映射”即可。
- 不做复杂骨骼编辑器替代。

### 6.2 必备能力

- 动画状态机映射：idle、walk、work、interact、hurt、death
- 事件帧标记：命中帧、采集帧、交互触发帧
- 方向适配：至少支持 4 向（后续可升 8 向）
- 资源一致性校验：动画名、骨骼插槽、皮肤名

## 7. 16x16 网格下人类角色像素规格

### 7.1 推荐基线

- 地面占格（脚底占用）：1 格（16x16 逻辑占格）
- 显示宽度：20 到 24 px
- 显示高度：40 到 48 px
- 首版建议：24x48 显示尺寸

### 7.2 碰撞盒建议

- 脚底碰撞盒：12x8 或 14x10
- 说明：碰撞只看脚底，不按全身轮廓计算，移动手感更稳定。

### 7.3 Spine 绘制与渲染约束

- 建议按 2x 稿制作：例如目标显示 24x48，则美术源稿可按 48x96。
- 运行时缩放至 0.5，提升镜头变化与 UI 预览稳定性。
- 采样模式使用 nearest/point，避免像素模糊。
- 位置尽量像素对齐，减少抖动。
- 少用大幅网格形变，优先刚性部件与骨骼旋转，维持像素风一致性。

## 8. 阶段里程碑建议

### 8.1 第 1 阶段（先跑起来）

- 完成 6 项 MVP 工具
- 跑通：建造 -> 采集 -> 种植 -> 任务触发 -> NPC 交互

### 8.2 第 2 阶段（可扩展）

- 加入任务/技能编辑器
- 加入 Spine 动画管理器最小版
- 加入存档迁移与自动化冒烟

## 9. 验收标准

- 仅改配置可新增 1 种地块、1 个作物、1 条任务、1 个技能。
- 配置热重载可在短时间内生效，且失败可回滚。
- 资源缺失不会崩溃，可自动回退并记录问题。
- 角色在 16x16 网格地图中尺度稳定，无遮挡穿帮。
- Spine 动画状态可被系统正确驱动，交互关键帧可触发逻辑事件。

## 10. 物种工具与角色模板工具迭代（轻骨架版）

### 10.1 新增目标

- 增加“物种工具”：支持基础骨架预览（仅节点与骨骼线条），可选叠加基础身体贴图（如未着装人类体型）用于预览。
- 增加“角色模板工具”：基于种族模板派生角色模板，选择种族后配置职业参数（如士兵、大夫）并查看属性与加成结果。
- 明确边界：复杂动画、网格形变、插槽蒙皮等高级功能仍在 Spine 内处理，工具仅负责模板配置与预览验证。

### 10.2 参考案例

参考：鬼谷八荒 的 角色面板与种族差异表达  
实现方式：以基础属性为核心，叠加流派/角色差异形成最终数值。  
适用性：适用  
本项目调整：采用“一级属性 + 二级加成”结构，先满足模板化配置与可视化预览。

参考：明日方舟 的 职业模板与数值派生  
实现方式：角色由职业定位决定基础面板倾向，再叠加个体差异。  
适用性：适用  
本项目调整：角色模板以“种族模板 + 职业模板 + 参数覆写”三段式组合输出。

参考：修仙模拟器 的 数据驱动角色定义  
实现方式：角色数据以配置表定义，运行时按规则解释。  
适用性：适用  
本项目调整：物种与角色工具均输出配置，不直接硬编码业务规则。

### 10.3 功能边界

#### 10.3.1 物种工具（Species Tool）

- 物种基础信息：`id`、名称、简介、标签。
- 基础动作集：`idle/walk/run/work/interact/hurt/death`。
- 轻骨架预览：
  - 节点定义（node id、x、y）
  - 骨骼连线定义（from、to）
  - 可选身体底图层（用于体型观察，不替代最终美术）
- 属性模板：
  - 一级属性（可扩展）：力量、敏捷、体质、精神（首版）
  - 二级加成（可扩展）：伤害、防御、治疗强度（首版）

#### 10.3.2 角色模板工具（Role Tool）

- 选择种族模板作为基底。
- 选择职业模板（如士兵、大夫、游侠）。
- 参数覆写：对一级属性与二级加成进行增减微调。
- 结果视图：实时展示“最终一级属性”与“最终二级加成”。
- 输出：可落盘角色模板配置，供 NPC/可玩角色系统引用。

### 10.4 数据模型（可扩展约束）

#### 10.4.1 属性字典可扩展

- 属性采用字典结构，不固定字段长度。
- 新增属性仅需在属性字典注册，无需改动工具核心流程。
- 建议字段约束：
  - `key`：机器标识（唯一）
  - `name`：显示名
  - `group`：`primary` 或 `bonus`
  - `defaultValue`：默认值
  - `visible`：是否在工具 UI 显示

#### 10.4.2 公式分层

- 最终一级属性 = 物种一级属性 + 职业一级调整 + 角色覆写值
- 最终二级加成 = 物种二级加成 + 职业二级调整 + 角色覆写值
- 后续扩展：允许加入装备、技能、状态等运行时来源，但不写入模板工具基础层。

### 10.5 配置建议（路径）

- `configs/gameplay/npcs/species.templates.yaml`：物种模板
- `configs/gameplay/npcs/role.templates.yaml`：职业模板
- `configs/gameplay/npcs/character.templates.yaml`：角色模板（派生产物）
- `configs/gameplay/npcs/attribute.dictionary.yaml`：属性字典（扩展入口）

### 10.6 工具交互流程

1. 在物种工具创建/选择物种。
2. 配置基础动作集与属性模板。
3. 调整轻骨架节点与连线，必要时挂基础体型贴图进行预览。
4. 在角色模板工具选择种族模板。
5. 选择职业模板（士兵、大夫等）并配置参数覆写。
6. 预览最终属性与加成，保存为角色模板。

### 10.7 与 Spine 的职责划分

- 本工具负责：模板配置、静态预览、属性与加成逻辑配置。
- Spine 负责：动画制作、蒙皮、插槽、时间轴事件、复杂骨骼行为。
- 约束：本工具不尝试替代 Spine 编辑器，只维护运行时所需最小结构。

### 10.8 新验收项

- 可新增至少 2 个物种模板（例：人类、兽族），并能独立配置一级属性与二级加成。
- 可新增至少 2 个职业模板（例：士兵、大夫），并正确叠加到种族模板。
- 轻骨架预览可显示节点与连线，可选显示基础体型底图。
- 新增属性字段时，无需修改工具流程，仅改属性字典与模板配置即可生效。
- 导出的角色模板可被 NPC/角色系统读取并得到稳定一致的最终数值。
