# UI 约束规范

本规范作为本项目 UI 设计与实现的统一约束入口，适用于页面配置、主题配置、皮肤配置与运行时渲染。

## 1. 布局约束

- 所有页面必须先定义整窗主结构，再定义局部组件。
- 页面布局必须以当前窗口内容区为统一基准，保持主视觉区、主交互区、辅助信息区的层级稳定。
- 功能卡片外框不得超出窗口内容区；内容超量时仅允许卡片内部纵向滚动。
- 主体开放式页面不得用单一封闭大卡片包裹主视觉与主操作区。

## 2. 组件与视觉约束

- 所有 UI 结构必须通过 YAML 配置定义，禁止在 JS 中硬编码组件树。
- 样式必须使用主题变量或公共样式参数，禁止直接写死业务页面颜色与尺寸。
- 同类组件必须共享状态样式，确保 normal、hover、active、disabled 行为一致。

### 2.1 边框按钮像素风约束

- 所有带可见边框的按钮必须采用像素风格表现，作为强制规则执行。
- 像素风边框按钮必须使用直角或像素切角轮廓，禁止圆角胶囊、柔和描边、发光描边、拟物高光边框。
- 按钮边框宽度、描边颜色、背景色必须来自主题 token，不得在页面配置中临时拼接视觉风格。
- 像素风按钮应保持整数像素边框与清晰边缘，避免非整数缩放或模糊阴影破坏像素识别。
- 无边框按钮可以按语义作为例外处理，但一旦声明边框，必须回到统一像素风边框体系。

## 3. 技术实现约束

- 页面配置负责结构与行为绑定，主题配置负责 token，皮肤配置负责覆盖与资源映射。
- 动态内容优先使用数据绑定，避免在运行时代码中查找组件并逐个改文案。
- 页面层与卡片层默认禁止横向滚动。

## 4. 自查清单

每次新增或修改 UI 后，必须确认：

1. 页面是否先定义了整窗主结构。
2. 主操作区是否处于整窗视觉主焦点。
3. 功能卡片外框是否全部位于窗口内容区内。
4. 页面与卡片是否不存在横向滚动。
5. 所有带边框按钮是否均为像素风直角或像素切角样式。
6. 边框按钮是否全部复用主题 token，而非临时硬编码。
